### 陷阱速查（error_list 三版累计）

1. **全量 pytest 是唯一验收**：单文件绿 ≠ 全量绿（全局 APScheduler 后台线程污染 —— 凡 monkeypatch `_get_db_session`/`get_db` 的测试 fixture 必须先 `stop_scheduler()`；F-085/098/110 fixture 已用 StaticPool+每任务新 session）
2. **RED 不转红 = 测试无效**：行为差异测试必须让新旧行为结果可区分（F-105 互补数据陷阱）；SQL 计数测试注意 SQLAlchemy 事件签名（首参 conn）与 `\nFROM` 换行缩进
3. **同类调用点全库枚举**：修一类 bug 先 `rg` 枚举（F-025 borrow service、F-018 price_*、F-093 死代码路径教训）
4. **迁移交付**：模型注释与迁移注释逐字一致；本机 MySQL `alembic upgrade head` + `alembic check` 当场跑，不标"没法跑"
5. **response_model 契约**：与 service 实际返回类型逐字段核对（F-010 cancel status int 教训）；dict 返回会被 FastAPI 生成 `{}` 默认契约，契约测试须排除空 schema
6. **pydantic after-validator** 只包装 ValueError/AssertionError，业务异常须 try/except 转 ValueError
7. **scheduler 任务测试**：任务内 commit+close 注入 session → 断言前先取 id、用新 session 复核
8. **提交纪律**：目标测试绿后才 commit；单主题 commit；不改断言糊弄；金额 Decimal/ROUND_HALF_UP；LIKE escape_like；时区 datetime.now()
