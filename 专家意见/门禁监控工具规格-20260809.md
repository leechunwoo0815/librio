# librio 门禁监控工具规格（2026-08-09）

> 本文件是你在 librio 实现"门禁实时监控工具"（重构原 `sleep 500; grep ... | tail -20` 命令）的唯一需求来源。
> 按本规格实现，不得自行扩大或缩小范围。有歧义先问，不要猜。

## 〇、原命令（你要重构的对象）

```bash
sleep 500; grep -E "passed|failed|PASS|FAIL|No new|OK:|PASSED" /tmp/librio_gates6.log | tail -20
```

- 用途：全量门禁（CI 同构十一关 + MySQL 并发 A-K）跑约 7-10 分钟，命令输出重定向到 `/tmp/librio_gates*.log`，本命令负责"等它跑完 → 提取结果行 → 看尾部 20 行"
- 痛点：`sleep 500` 是死等（pytest 单跑 432s，等短了抓不到，等长了浪费时间）；`grep` 无错误检测；`tail -20` 无统计计数；`gates6.log` 文件名硬编码
- 重构目标：**轮询监控代替死等、错误检测、实时增量输出、结果计数统计**

## 一、监控对象（唯一）

**门禁输出日志**：`/tmp/librio_gates_*.log`（含日期后缀，如 `/tmp/librio_gates_20260809.log`、`/tmp/librio_gates2_20260809.log`）

- 产生方式：运行 CI 同构十一关时 `venv/bin/... >> /tmp/librio_gatesN_YYYYMMDD.log 2>&1`
- 日志结构：按段输出，每段以 `===== 段名 =====` 开头，末尾固定完成标记：
  ```
  ===== PYTEST =====
  883 passed, 69 warnings in 409.96s (0:06:49)      ← pytest 结果行
  ===== BEHAVE =====
  211 scenarios passed, 0 failed, 0 skipped        ← behave 结果行
  ===== RUFF =====
  All checks passed!
  ===== CONTRACT / MODEL / WIRING / CONFIG / INTEGRATION / ALEMBIC / MYSQL =====
  [PASS] A 预约并发超卖（行锁）: 成功 5/100 ...     ← MySQL 各场景
  ===== GATES DONE =====                            ← 全部完成标记
  ```
- 关键事实：pytest 独占 ~430s（409-432s 实测），behave ~140s，MySQL A-K 数分钟，**总耗时 7-10 分钟**；日志**边跑边写**（非一次性落盘）

## 二、功能需求（4 项，全部必须）

1. **实时监控（替代 sleep 死等）**：轮询指定门禁日志，**增量输出**新写入的结果行
   - 每轮询周期只读新追加的内容（`seek` 到上次位置），不重扫全文
   - 检测到完成标记 `===== GATES DONE =====` → 打印汇总统计并**自动退出**（不再轮询）
   - 提供 `--timeout` 超时保护（默认 900s，超时未完成 → 报错退出码 3）
2. **错误检测**：实时识别失败行并醒目输出
   - 判定规则（任一命中即失败）：行含 `failed`（如 `0 failed` 的兄弟行 `N failed`）、`FAIL`、`PASSED` 之外的大小写变体、`ERROR`、`Traceback`；pytest 结果行 `N passed, M failed` 中 `M > 0`
   - 失败行输出加 `[FAIL]` 前缀并标红（终端 ANSI，非 tty 时省略 ANSI）
3. **结果计数输出**：实时累计统计 + 退出汇总
   - 实时：每轮询周期打印增量行数；每 `--stats-every` 秒打印累计统计
   - 退出汇总（`===== GATES DONE =====` 检测到后）：
     ```
     [summary] passed=1033 failed=0 PASS=11 FAIL=0 OK=6 No-new=1
     [summary] 段: PYTEST✓ BEHAVE✓ RUFF✓ CONTRACT✓ MODEL✓ WIRING✓ CONFIG✓ INTEGRATION✓ ALEMBIC✓ MYSQL✓
     ```
   - 计数口径：`passed`/`failed` 计 pytest+behave 结果行中的数字（多行累加）；`PASS`/`FAIL` 计 `[PASS]`/`[FAIL]` 前缀行数；`OK:` 计 `OK:` 开头行数；`No new` 计 alemlbic 无迁移行
4. **CLI 参数化**（默认值指向本工具的实际用法，不硬编码判断逻辑）：

   | 参数 | 默认值 | 说明 |
   |---|---|---|
   | `--log-file` | `/tmp/librio_gates_*.log` 中修改时间最新的一个 | 找不到则报错列出候选文件，退出码 2 |
   | `--pattern` | `passed\|failed\|PASS\|FAIL\|No new\|OK:\|PASSED` | 结果行匹配模式（原命令 grep -E 的原文） |
   | `--done-marker` | `===== GATES DONE =====` | 完成标记，检测到即汇总退出 |
   | `--interval` | `5` | 轮询间隔（秒） |
   | `--stats-every` | `60` | 累计统计打印间隔（秒）；0=仅退出时打印 |
   | `--timeout` | `900` | 超时（秒），超时未完成 → 退出码 3 |
   | `--tail-lines` | `0` | 启动时先回扫文件末尾 N 行纳入首轮统计；0=不回扫 |

## 三、实现要求

- **语言**：Python 3（项目 `venv/bin/python`），标准库即可（`argparse`/`glob`/`time`/`pathlib`/`os`），**禁止新增第三方依赖**
- **文件位置**：`scripts/monitor_gates.py`（librio 现有运维脚本统一在 `scripts/`）
- **增量读取**：Python 文件对象维护偏移（`file.tell()` / `file.seek(end)`），每轮读 `while line := f.readline():` 处理新行；处理文件轮转/重建（inode 或大小变化时重新打开）
- **匹配逻辑**：默认按 `--pattern` 正则对每行匹配（`re.search`），命中即"结果行"进入计数与输出；错误检测在结果行基础上叠加 §二.2 规则（`failed`/`FAIL` 等）
- **输出格式**：
  - 实时结果行：`[ts] <原行内容>`（失败行 `[FAIL]` 前缀）
  - 周期统计：`[stats] period=+N total=M passed=X failed=Y`
  - 汇总见 §二.3；所有统计行前缀 `[summary]`/`[stats]`
- **退出码**：正常完成（GATES DONE）→ 0；`--exit-on-error` 且发现失败行 → 1；文件不存在 → 2；超时 → 3；工具异常 → 4

## 四、边界与验收

| 场景 | 期望行为 |
|---|---|
| 日志不存在 / 通配符无匹配 | 报错列出 `/tmp/librio_gates*` 候选，退出码 2（不无限等待） |
| 日志边跑边写（实测场景） | 增量输出，不重扫、不重复计数 |
| 检测到 `===== GATES DONE =====` | 打印汇总统计，自动退出，退出码 0 |
| pytest 结果 `N passed, M failed` 且 M>0 | 该行标 `[FAIL]`，汇总 failed 计数正确 |
| 中途 `Ctrl+C` | 打印当前累计统计，退出码 0（或 1 若已见失败行） |
| 超时未完成 | 报错 + 当前统计，退出码 3 |

验收自测（交付时贴真实输出）：
1. `venv/bin/python scripts/monitor_gates.py --interval 1 --stats-every 5 --timeout 30` 对一个正在写入的 `/tmp/librio_gates_test.log` → 增量输出 + GATES DONE 后自动汇总退出
2. 手工造含 `2 failed` 的行 → `[FAIL]` 标记 + `--exit-on-error` 退出码 1
3. 不存在的文件名 → 退出码 2
4. 对历史真实文件 `/tmp/librio_gates2_20260809.log` 跑一遍 → 汇总统计与实测一致（PASS=9/OK=2/No-new=1 等，以实际为准）

## 五、禁做清单

- 禁止修改 `backend/`、`scripts/` 其他脚本、`CLAUDE.md` 门禁命令（监控工具是只读消费者）
- 禁止新增依赖、禁止跑任何门禁命令本身（本工具只读日志文件）
- 禁止用 `sleep` 固定死等 + `tail` 子进程实现（必须纯 Python 增量轮询）
- 禁止把默认参数硬编码成不可覆盖的常量（默认值可被 CLI 覆盖即可）
