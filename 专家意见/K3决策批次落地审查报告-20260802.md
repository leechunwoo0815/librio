### 🔴 P0-1：押金支付单号列类型错误 → MySQL 生产押金支付全链路 500

**严重级别**：P0（资金入口，生产必现）

**证据链**（已逐行核实）：

| 位置 | 内容 |
|---|---|
| `backend/domain/deposit/models.py:41` | `pay_order_id = Column(BigInteger)` |
| `backend/domain/deposit/service.py:54-56` | `_generate_order_no()` 返回**字符串** `f"DP{uuid.uuid4().hex[:24].upper()}"` |
| `service.py:92` | `pay_deposit` 把字符串写入 `pay_order_id`（BigInteger 列） |
| `service.py:260` | `repay_deposit` 同样写入字符串 |
| `service.py:178` | 回调匹配 `DepositRecord.pay_order_id == order_no`（字符串 vs 整型列） |
| `backend/domain/deposit/schemas.py:33` | 声明 `pay_order_id: str | None`，与模型类型矛盾 |
| `alembic/versions/v31_omo_tables.py:153` | 迁移中亦为 `sa.BigInteger()` |

**为什么测试没抓到**：
- SQLite 宽松类型（dynamic typing）存字符串不报错，回调匹配也能靠隐式转换通过
- MySQL 8 默认 `STRICT_TRANS_TABLES` 下，`pay_deposit`/`repay_deposit` 写入非数字字符串到 `BIGINT` 列直接 `DataError` → HTTP 500
- `tests/unit/test_deposit_service.py` 仅 3 个状态断言（创建/查询/回调 mock），未覆盖真实写库路径
- 该 bug 从旧 commit（`6b29543` V3.10、`3d7a354`）遗留至今，非本次批次引入，但本次 B12 资金链路审查暴露

**影响**：押金缴纳 / 重新缴纳 / 回调核销在 MySQL 生产环境全部不可用。押金是核心资金入口，阻断所有依赖押金的流程（借阅、罚款抵扣、退款）。

**修复方向**：
1. 迁移：`pay_order_id` 列改 `String(64)`（配数据回填），或
2. 拆列：`pay_order_id` 存网关返回的数值 ID，另加 `out_trade_no` 字符串列承载 `DP...` 单号
3. 补回归测试：用 MySQL 严格模式（或 mock 列类型断言）覆盖写库路径

### 🟠 P1-2：C2 测验冷却时区错配 → 生产环境测验后约 8 小时无法重测

**严重级别**：P1（功能阻断，生产必现）

**证据链**：

| 位置 | 内容 |
|---|---|
| `backend/domain/advancement/service.py:146` | `now_utc = datetime.now(timezone.utc).replace(tzinfo=None)`（**UTC**） |
| `backend/common/base_model.py:35` | `create_time = Column(DateTime, default=func.now())`（MySQL 下为**东八区本地时间**） |
| `service.py:153/161` | 冷却查询 `Quiz.create_time > now_utc - timedelta(minutes=cooldown)` |

**计算验证**：本地时间 10:00（= UTC 02:00）时，`create_time=10:00` vs `now_utc=02:00`，差值 `now_utc - create_time = -8h`，`remaining = 10min - (-8h) = 490min` → 提示"请 490 分钟后重试"。任何最近 8 小时内的测验都命中"冷却中"。

**为什么测试没抓到**：
- SQLite 的 `CURRENT_TIMESTAMP` 本身就是 UTC，与 `now_utc` 一致，测试环境自洽
- 生产 MySQL `NOW()` 返回会话时区（默认系统时区东八）→ 8 小时偏差

**影响**：C2 决策（重考间隔限制）在生产实际变成"测验后 8 小时冷却"，D4 达标流程（读完→测验→自动审核）被阻断，低龄重考不可用。

**修复方向**：统一时区口径——`create_time` 存 UTC（MySQL 连接参数 `timezone` 或插入时显式 UTC），冷却比较全链路用 `datetime.now(timezone.utc)`；或保持本地时间但 `now_utc` 改为本地 `datetime.now()`。建议写一个断言时区一致的回归测试。
