#### 3.4 Token/会话安全审查
- **8 项风险，6 项已修复 + 2 项设计选择不修改**：
  - S-01 P0：`set_current_child` 缺 Child 归属校验 → 已修复，加 `verify_child_ownership`
  - S-02 P0：`add_to_shelf/add_favorite/start_quiz` 缺 child_id 校验 → 已修复，加 `verify_child_ownership`
  - S-03 P0：改密码后旧 Token 仍有效 → 已修复，`token_generation` 机制（改密码/禁用后旧 Token 立即失效）
  - S-04 P1：User 表缺 status → 已修复，加 `status` 字段（默认 active），可禁用用户
  - S-05 P1：测试 Token 后门 → 已修复，生产环境 `ENABLE_TEST_TOKEN=False` 强制校验（移入 `model_validator`）
  - S-06 P1：默认 SECRET_KEY → 已修复，生产环境禁止默认值（移入 `model_validator`）
  - S-07 P1：不引入 refresh token → 设计选择不修改，理由：`token_generation` 已提供服务端强制失效能力，access token 短有效期（2h）+ 吊销机制满足安全需求
  - S-08 P1：logout 仅前端清除 → 设计选择不修改，理由：服务端无状态 JWT 架构下，`token_generation` 吊销等效于服务端注销；前端清除 token + 后端 token_generation 校验已形成完整闭环
- Alembic migration 028：User 加 `status` + `token_generation`，Admin 加 `token_generation`
- 报告：`token_session_security_audit_20260722.md`、`token_security_fix_report_20260722.md`
