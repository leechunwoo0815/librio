- 删除：`backend/domain/admin/router.py`（568 行 God router 拆分）

### Phase 2：RBAC 体系（07-07 ~ 07-09）

#### Phase 2.1 — 模型与种子
- 三阶段审查修复：super_admin 缺 2 权限、`get_data_scope(admin_role_id=None)` 返回 "all"→"none"、`get_scoped_child_ids` dead code、RolePermission 查询未过滤 is_deleted、种子幂等不清理已移除权限码、role_permission 缺 FK、Admin.role_ref lazy→joined
- 最终：权限码 135 个，34 个分组，无重复，无幽灵，Alembic 迁移完整，种子幂等，数据隔离 3 角色覆盖

#### Phase 2.2 — 路由权限检查
- 57 个写操作端点补全 `require_perm`（总计 181 个调用，排除定义和 import）
- 数据隔离启用（8 个列表端点传递 `get_scoped_child_ids`）
- `require_role`→`require_perm` 迁移完成（9 个用户端路由）
- 页面路由 token 验证 `except Exception` 改为 `logging.exception`
- `admin.view` 幽灵权限→改为 `admin.list`

#### Phase 2.3 — 前端权限控制（保守模式）
- localStorage 过期不操作 DOM，`applyPermissions()` 只做减法
- `data-perm` 空格分隔 OR 逻辑
- 侧边栏从文字匹配迁移为 `data-perm` 声明式控制
- `user_can()` 来自 token 实时解析
- `reapplyPermissions()` 可重入函数处理动态渲染元素

#### Phase 2.4 — 消息系统改造
- 全部用户群发从 N 条 SystemMessage 改为 1 条共享消息（`user_id=NULL`，`target_role_codes` 标记可见分组）
- 用户端查消息 OR(user_id==mine, target_role_codes IS NULL, target_role_codes CONTAINS my_group)
- `MessageReadStatus` 表 + migration 017（共享消息已读追踪）
- `_USER_GROUP_MAP` 去掉 status=3/4（分组从 5 组降为 3 组：trial/observation/member）

#### Phase 2.5 — 角色管理
- 7 个 API 端点：roles GET/POST, roles/{id} GET/PUT/DELETE, roles/{id}/permissions GET/PUT
- `set_role_permissions` 全量替换（软删除+重新激活）
- `delete_role` 有 admin_count 保护 + 系统角色不可删
- `_resolve_admin_role_id` 向后兼容旧 role 整数
- roles.html 系统角色卡片修复（`!r.is_system` 条件）
