## 五、纪律与陷阱（累计，最新在前）

- pytest/behave 并非纯内存：9 个用例与 40 个 behave error 依赖本机 MySQL（无 MySQL 环境会 fail）——"全绿"结论限定于开发机环境（FINAL-3.0 勘误）
- RBAC 种子无启动钩子：新增权限码后必须手动对开发库重跑 seed_roles/seed_permissions/seed_role_permissions（幂等，生产同理）
- 给 User/Child 加列后：① 迁移含存量回填（exited_at 用 update_time 近似、paid_member_ever 按订单）② ChildResponse 等 schema 要同步加字段 ③ 表结构.md 注记
- SQLite 测试里 create_time 用构造传参改老，update_time 有 onupdate 必须用 `db.execute(text("UPDATE ..."))` 绕过 ORM；exited_at 无 onupdate 可构造传参
- ConfigService.set_config 需要 config_audit_log 表：测试文件要 `import backend.common.config_audit_model`
- 语音录音 voice_recording.text_content/duration_seconds 为 NOT NULL，测试造数据必填
- 管理端新页面四件套：模板 html + js/pages/x.js + css/pages/x.css + admin_page_router（PAGE_PERM_MAP + 路由）+ base.html 侧边栏 data-perm；data-action 必须能被 wiring 7 种正则捕获
- 小程序 wxss 禁非注释 hex（P2-10 红线）：颜色一律 var(--accent)/var(--surface) 等 token
- wxml 里 iOS 分支若 wx:if/else 互斥，按钮要放进 iOS 分支内（否则 iOS 用户看不到按钮）
- 编辑文档 old_string 含下一节标题时 new_string 必须保留原标题（防吞标题）
- 后台门禁任务会读到未提交的半批改动：每批先完整再跑门禁；pytest 全量约 5-6 分钟，后台任务 timeout 给 900s
- alembic check 连的是开发 MySQL：新迁移必须先 upgrade head 再 check
- with_for_update() 在 SQLite 下为 no-op，单测只验功能
- 审查类反馈逐条给"属实/不成立/非bug/可接受风险"结论，不粉饰不硬顶
- 迁移改列后 alembic check 会报注释漂移：迁移文件里补 alter_column comment
- BDD 步骤硬编码配置默认值会与服务端新默认脱节——步骤默认值必须与服务端同步
- ConfigService._cache 进程级共享：测试间 set_config 后需 invalidate（fixture 尾部清理）
- behave 步骤名全局唯一；admin.username/role.code 唯一约束需 uuid 后缀
- timedelta.days 截断：剩余天数预期值按截断后整数算
- check_model_consistency.py 被 import 会强制 DATABASE_URL=sqlite
- integration 需 MOCK_PAYMENT=true MOCK_SMS=true DEBUG=true；十关命令在 CLAUDE.md §六
