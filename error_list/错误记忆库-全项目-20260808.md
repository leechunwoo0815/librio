## 一、本轮新增错误（五要素）

### E-20260808-01 F-010 响应契约与 service 实际返回类型不符（behave 3 error 回归）
- 事实：EnrollmentActionResponse.status 定义为 str，cancel/sign-in 实际返回 int
  （enroll 是 str、cancel/sign-in 是 int、errors 是 list[dict]、mark_read 返回 dict）——
  response_model 序列化 500，behave 抓出 3 error。
- 被抓方式：批末全量 behave（基线 211/1369 全绿 → 3 error）。
- 根因：只看"有响应"未逐端点核对**实际返回类型**（同一字段不同端点类型不同；
  dict 返回被 FastAPI 默认 `{}` 契约掩盖，契约测试第一版也因此假绿）。
- 修复：`status: int` 修正 + 契约守护测试排除空 schema。
- 防复发：补 response_model 必须列出端点返回结构矩阵（字段×类型×分支）；
  契约测试断言"非空 schema"而非"content 存在"。

### E-20260808-02 SQL 计数守护测试两次假绿（F-025）
- 事实：① SQLAlchemy 2.x `before_cursor_execute` 首参是 conn 非 statement，初版监听器
  恒记 Connection 对象，条件永远 False；② SQL 文本用 `\nFROM user` 换行缩进，
  `" FROM user "` 前后空格匹配失效。两处叠加导致"移除 joinedload 测试仍绿"。
- 被抓方式：RED 实证（撤修复行不转红）自抓。
- 根因：对框架事件签名和 SQL 渲染格式想当然，未先打印真实语句。
- 修复：正确签名 + 正则 `\bFROM\s+user\b` + 排除 JOIN/IN。
- 防复发：写 SQL 计数测试先跑一次"无修复"版本确认能抓到再验收；RED 不转红=测试无效。

### E-20260808-03 F-036 增量窗口 or 0 兜底清零历史字段
- 事实：增量模式下窗口外孩子不在聚合 map，`words_map.get(cid) or 0` 把历史值当 0 修正。
- 被抓方式：新增"旧数据不进窗口"测试转红（孩子字段被清 0）自抓。
- 根因：全量逻辑假设"所有孩子都在 map 中"，增量破坏了该不变量但未同步改修正语义。
- 修复：仅遍历受影响孩子，且只修正本次聚合到的字段；每月 1 日全量兜底。
- 防复发：加"窗口/增量"类逻辑时逐条检查原不变式（全量假设）是否被破坏。

### E-20260808-04 pydantic after-validator 不包装业务异常
- 事实：model_validator 抛项目 `ValidationError` 原样冒泡，`pytest.raises(ValidationError)`
  不匹配，测试失败。
- 根因：pydantic v2 只把 ValueError/AssertionError 转 ValidationError。
- 修复：validator 内 try/except 转 ValueError。
- 防复发：schema validator 一律抛 ValueError，业务异常留给 service 层。

### E-20260808-05 迁移注释与模型注释漂移致 alembic check 红
- 事实：迁移 053 注释短于模型列注释，upgrade 后 check 报 modify_comment。
- 根因：模型列与迁移文本手写不一致。
- 修复：对齐后重跑 upgrade（开发库手动 ALTER 同步列注释）+ check 绿。
- 防复发：新迁移落库后立即 upgrade head + check；注释文案以模型为唯一源。

### E-20260808-06 测试 session 被任务 close 致 detached
- 事实：scheduler 任务 finally `db.close()` 关闭注入 session，测试对象 detached，
  断言 user.id 抛 DetachedInstanceError。
- 修复：断言前先取值（uid = user.id）。
- 防复发：测 scheduler 任务（内部自建/关闭 session）时对 fixture 对象先取原始值。

### E-20260808-07 提交时测试仍红（F-037 断言 API 误用）
- 事实：RangeExpression 无 .value 用 .first，测试红时误提交，随后立即修正。
- 根因：未等测试绿就 commit（违反"测试通过再提交"）。
- 修复：补修正 commit `843a53b`。
- 防复发：commit 前强制 `git status` + 至少跑目标测试一次绿。

### E-20260808-08 死信重放语义（设计防错，非错误）
- 事实：event_bus.publish(db=None) 失败会吞异常并自动记新死信，重放无法判断成功。
- 处理：重放改直接调 handler 独立事务，成功才标记 resolved_at——人工控制语义。
- 固化：凡"人工重放/重试"场景，避免复用自动重试路径的吞异常语义。
