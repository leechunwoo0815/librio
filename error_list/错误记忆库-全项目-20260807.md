2. 测试：兄弟路径各补一条用例（即使不是审查点名项）。
3. 提交前自查：本次修复涉及的概念，全库还有几处？一处不落。

**错误清单**：

| 测试只覆盖点名路径 | F62 | appeal 没测，漏改不可见 |
| 押金退款活跃借阅校验从未真实触发 | K3 全量修复报告 | B2 假 step |
| test_report_pdf 接不住 OSError | 修复交付核验 | try/except ImportError 类型不全 |

**根因机制**：测试证明的是"我写的流程"，不是"真实契约/真实并发/全部入口"。假绿让
其余所有错误得以通过门禁——它是错误放大器。

**防复发动作**：
1. 断言必须"真值"：接口返回字段、数据库实际状态、消息内容，禁状态码集合恒真、禁空断言。
2. 测真实路径：调真实 service/API，禁 ORM 造数、禁自带公式、禁手动扣库存 hack。
3. 关键修复做 RED→GREEN：撤掉修复行，测试必须转红（证明测试真守护）。
4. 契约测试用"差异场景"（部分退款 total≠refund、拒绝分支、非 SUCCESS 回调）。
5. MySQL-only 检查（alembic check、并发、时区）必须真跑，不标"没法跑"。

## 四、正反案例（哪些做法值得固化，哪些必须杜绝）

### 正面（被审查方验证通过的正确做法）
1. **F12 RED→GREEN 实证**：临时撤修复行测试转红，恢复全绿——"测试真实守护修复点"
   成为项目标杆，多次被专家引用。
2. **streak 修复**（我）：自然日重算算法被外部专家亲验"幂等/断签/同日多事件三性质成立"，
   且比要求多做了一步（now 快照防时钟漂移）——主动加固被认可。
3. **F8 day-0 补刀**：被专家抓到边界后补 0<=days<=grace + now 守卫 + 双侧用例——
   边界矩阵思想从此固化。
4. **P1-1 JWT 时区反驳成立**：审查方误判时给出证据链（jose 内部 UTC 无交叉），
   不盲从审查结论——"可辩驳"是审查纪律的一部分。
5. **P3-a 专家误判被纠正**（我）：token 定义被误判为遗留硬编码，独立复核纠回——
