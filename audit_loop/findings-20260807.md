### [F-20260807-001] mark_book_lost 中 Book.total_stock 读-改-写无行锁
- 级别: P2（并发危害需 MySQL 实证；SQLite 行锁 no-op 不得据此下结论）
- 维度: 1.2 并发与事务
- 文件: backend/domain/deposit/service.py:475（查询）→ 509-510（赋值）
- 事实:
  ```python
  book = self.db.query(Book).filter(Book.id == record.book_id).first()  # 无 with_for_update
  ...
  book.total_stock = max((book.total_stock or 0) - 1, 0)
  book.available_stock = max((book.available_stock or 0) - 1, 0)
  ```
- 证据: 同函数内 BorrowRecord(L461-466) 与 Child(L486-490) 均带 with_for_update，唯 Book 无；历史 transaction_lock_audit_20260721.md P0-2/P0-3 只点名 Child（已修，checkpoint.md F2），Book 写点为同类漏网。
- 触发: 两个并发 mark_book_lost 命中同一 book（不同借阅记录/不同副本）→ 两事务均读到 total_stock=N → 各写 N-1，丢一次扣减。
- 影响: total_stock/available_stock 计数偏高 1；由每日 reconcile_stock（scheduler.py:256，03:00，distributed_lock）自动纠正，无持久性危害。
- 建议: book 查询补 `.with_for_update()`，或改用原子 `db.query(Book).filter(...).update({...})`（与 BookCopy L502 一致）。
- 排重: grep 确认 transaction_lock_audit 仅点名 Child；checkpoint F2 只覆盖 Child 补锁；F41 库存对账口径为待甲方项，本发现为行锁缺口，不冲突。
