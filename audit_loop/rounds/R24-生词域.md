## [F-20260808-072] lookup_word 不传 child_id 时查词限额计数无效——试读用户可无限查词绕过 30 次/天上限 — P3

- **级别**: P3（观察项；业务规则绕过，无资金/安全；前端正常传 child_id 不受影响）
- **维度**: 2 状态机 × 业务规则（交叉维度；与 F-060 试读页数绕过同类）
- **文件**: `backend/domain/vocabulary/router.py:27-44`（lookup_word）/ `backend/domain/vocabulary/service.py:238-264`（check_lookup_allowed）/ `:266-290`（get_today_lookup_count）
- **事实**:
  - lookup_word 端点（router.py:27-44）：`child_id: int | None = None` 可选（L38）→ `check_lookup_allowed(current_user.id)`（L37，无条件执行）→ `if result and child_id: record_lookup(...)`（L40-42，**仅传 child_id 才记生词本**）
  - `check_lookup_allowed`（service.py:238-264）：试读用户（无 OBS/OFF 孩子）查 `get_today_lookup_count`（L256-259）→ 基于 `UserVocabulary.last_review_time >= today_start` 计数（service.py:273-283）
  - **计数与写入分离**：计数依赖 UserVocabulary 表有记录，但 lookup_word 不传 child_id 时**不写 UserVocabulary**（record_lookup 不执行）→ count 恒 0 → 30 次/天上限永不触发
  - 前端 reader 页查词正常传 child_id（api.js:41 lookupWord + reader.js 传 child_id）→ 计数有效；**直接调 API 不传 child_id 即绕过**
- **证据**: ① router.py:37-42（check 无条件 + record 有条件）；② service.py:256-283（计数基于 UserVocabulary）；③ 排重 grep：findings 无"查词限额绕过"命中（L1114 为配置对照"查词 30 次 ↔ vocab_lookup_limit=30 ✓"，未审绕过）；F-060（试读页数绕过）为 reading 域不同面
- **触发**: 试读用户（未升级会员）直接调 `GET /vocabulary/lookup/{word}`（不带 child_id 参数）→ 查词开关开启时无限查词，30 次/天上限失效
- **影响**: 试读查词付费墙（vocab_lookup_limit=30/天）形同虚设——试读用户可无限查词（不受限）。查词本身免费（产品目的是促升级），无资金/安全；数据可信度影响：查词不记生词本（record_lookup 跳过）→ 生词本/学习统计缺查词记录（对试读用户）
- **建议**: ① check_lookup_allowed 的计数改为**独立查词计数表**（或对不传 child_id 的调用单独计数/拒绝）；② 或 lookup_word 强制要求 child_id（归属校验 + 计数一体）；③ 或计数逻辑改为"查词请求本身计数"（中间件/独立表），不依赖 UserVocabulary
- **排重**: 已 grep 确认不在 F-001~071 / C-001~116 中；F-060（试读页数绕过 end_session）为 reading 域同类绕过模式，本项为 vocabulary 查词限额，不同面
