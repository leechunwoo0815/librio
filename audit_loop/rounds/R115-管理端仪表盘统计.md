## [F-20260808-105] week_lost_members 流失统计用 update_time 而非 exited_at——周流失率口径不准（P3）

- **级别**: P3（低：统计口径准确性，影响管理决策数据；无资金/安全）
- **位置**: backend/domain/admin/services/dashboard_service.py:79-88（week_lost_members）
- **类别**: 统计口径缺陷（数据准确性）
- **事实**: week_lost_members 判定"本周流失"用 `Child.update_time >= week_ago AND status == EXPIRED`——但模型
  有专门的 `exited_at`（child/models.py:82-86"退出时间，H5 数据保留计时基准，EXITED 迁移时写入"），update_time
  是**任意字段更新**时间戳（base_model.py:42-43 `onupdate=datetime.now`）——两者语义不同
- **证据**:
  - dashboard_service.py:79-88：`Child.update_time >= week_ago` + `status == EXPIRED`
  - base_model.py:42-43：update_time 任何字段 update 都刷新（onupdate=datetime.now）
  - child/models.py:82-86：exited_at 为精确退出时间（EXITED 迁移时写入，复活清空——R112 已核 revive 清空逻辑）
  - **误计场景**：① EXPIRED 孩子本周因监护变更/备注/其他字段更新 → update_time 刷新 → **误计本周流失**；
    ② 真实上周退出的孩子本周无任何更新 → update_time 未刷新 → **漏计本周流失**
- **触发**: 管理端周流失报表查看（运营决策依据）
- **影响**: 周流失/新增对比数据失真（流失偏高或偏低）→ 运营决策依据错误（如误判流失潮）；无资金/安全。
  P3 弱（报表数据，可人工甄别）
- **建议**: 改用 `Child.exited_at >= week_ago AND status == EXPIRED`（精确退出时间口径）；若存量数据 exited_at
  缺失（迁移前记录），可退化用 update_time 兜底或标注口径
- **排重**: grep 无"流失统计/exited_at"历史；R103（报告管理聚合）不涉此字段；H5（exited_at 语义）R112 已核
  revive 清空，本条为统计消费侧首次报
