## [F-20260808-098] send_overdue_reminders 无去重——手动重复触发全量重发逾期提醒（P3）

- **级别**: P3（观察项；消息骚扰/体验，无资金/安全；触发依赖运营重复点击）
- **位置**: backend/domain/admin/services/message_service.py:169-238（send_overdue_reminders）
- **类别**: 重复提醒无去重（模式⑪ 家族，F-085 同类漏改第 2 入口——模式 1 防复发红线）
- **事实**: send_overdue_reminders 每次调用都对**全部**逾期记录（get_overdue_records 全量 BORROWING+OVERDUE）
  重新创建 SystemMessage（L221-229）——**无"已提醒过"标记/去重**；同一逾期记录再次调用 → 再次推送相同提醒
- **证据**:
  - borrow/repository.py:46-56 get_overdue_records：status IN (BORROWING, OVERDUE) + due_date < now——逾期记录
    **持续匹配直到还书**，无已提醒过滤
  - message_service.py:204-229：循环内无条件 add SystemMessage（无 last_remind_at / 无去重查询）
  - 调用方 admin_borrow_router.py:158 为**管理端手动按钮**（非定时任务）——运营可反复点击
  - **同类对照**：F-085（R55 scheduler remind_pending_submissions 无去重，每日 11:00 轰炸）——同一"提醒无去重"
    模式在**定时链已报、手动链漏改**（防复发红线 1：同类漏改，修复须两入口同改）
- **触发**: 运营对同一批逾期记录连续点击"发送逾期提醒"两次以上（或间隔重试）
- **影响**: 家长收到多条完全相同的逾期提醒（消息轰炸，体验差）；无资金/安全。手动低频 + 运营自律则弱
- **建议**: ① 加"已提醒"标记（BorrowRecord.last_remind_at 或提醒消息表查重）；② 或发送前按 user 查近期同类消息
  去重；③ 或返回"上期已提醒 N 条，本次跳过"；修复时与 F-085（scheduler 链）统一模式处理
- **排重**: F-085 已报 scheduler pending 链；send_overdue_reminders 手动链首次报；R55 C-148（due 提醒递增设计）
  与本条不同（due 按日期递增是设计，逾期全量重发是缺陷）；grep 无 message_service 去重历史
