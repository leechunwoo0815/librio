### [F-20260807-047] 维度 X.2 定时任务 × 资金 — is_first_overdue 无锁 count，任务×还书跨事务并发双双免罚 — P3 观察
- 方法: 交叉维度第二项。核对定时任务（mark_overdue_books）与还书路径（return_book）的罚款公式与首次免罚判定的并发一致性。
- 事实: 金额公式口径一致（两路径共用 fine_policy.py 的 apply_fine/get_overdue_policy/sync_outstanding_fine，无公式分叉）✓。但 `is_first_overdue`（fine_policy.py:58-69）是对同一 child 其他逾期记录的**无锁 count 查询**。竞态场景（同一 child 两本 OVERDUE 书 A/B）：
  1. 任务事务 T1 锁 record A（scheduler L1581 with_for_update）→ `is_first_overdue(child)` count：B 尚 BORROWING 未标记 → 0 → A 免罚
  2. 还书事务 T2 锁 record B（borrow/service.py:228 with_for_update）→ `is_first_overdue(child)` count：A 在 T1 未提交，快照读不见 → 0 → B 免罚
  3. 两事务提交 → A、B 均 fine_waived=1，"每孩仅一次"语义被打破
  - 任务内部循环靠 autoflush 保证同事务内只免一次（A 先标记后 B 的 count 可见）✓；跨事务窗口（T1/T2 未提交期重叠）极窄。
- 影响: 单孩两本同时首逾时可能双免（损失 1 本书罚款上限=定价×50%，几十元量级）；需 MySQL 实证，SQLite 行锁 no-op。P3 观察。
- 建议: is_first_overdue 判定改为在 child 行锁内执行（两路径先锁 child 再 count），或依赖同步 outstanding 阶段的 child 锁统一串行化。
- 排重: R1 3.4（公式一致）查公式不查并发；R2 13.1（F-044）查 N+1；本轮交叉维度新增。
