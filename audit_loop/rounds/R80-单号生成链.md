## [F-20260808-090] order.generate_order_no 弱熵（时间戳+4 位随机）并发同毫秒碰撞无重试——IntegrityError 500 — P3

- **级别**: P3（观察项；极低概率 + DB unique 兜底无数据损坏；同类不一致）
- **维度**: 4 API 契约（单号生成面）
- **文件**: `backend/domain/order/repository.py:31-36`（generate_order_no）/ `backend/domain/deposit/service.py:54-56`（_generate_order_no 对照）/ `backend/domain/order/models.py:40`（order_no unique）
- **事实**:
  - order `generate_order_no`（repository.py:34-35）：`MW + int(time.time()*1000) + random.randint(1000,9999)`——随机部分仅 4 位（9000 种）
  - **并发同毫秒碰撞**：两请求同一毫秒 + 相同 randint → 同 order_no——同毫秒并发下单（秒级几十单场景）碰撞概率 1/9000（非零）
  - **无重试**：碰撞时 Order.order_no unique 约束（models.py:40）拦截 → IntegrityError 未捕获 → **create_order 500**（用户重试）
  - **对照**：deposit `_generate_order_no`（L55）`DP + uuid4().hex[:24]`（96 位强熵）——碰撞可忽略；**同类不一致**（order 弱熵 / deposit 强熵）
- **证据**: ① order/repository.py:34-35 randint 4 位；② deposit/service.py:55 UUID24；③ 排重 grep：findings 无"order_no 碰撞/生成弱熵"命中（L559 提"单号唯一"为押金回调面）
- **触发**: 高并发下单（同一毫秒多个 create_order 且 randint 碰撞）→ 500
- **影响**: 偶发 500（用户重试可恢复）；DB unique 兜底无数据损坏/无重复订单。极低概率（需同毫秒 + 1/9000），P3 观察
- **建议**: ① 对齐 deposit 模式改用 UUID 段（如 `MW + uuid4().hex[:8].upper()` 或时间戳+UUID4）；② 或生成时查重/捕获 IntegrityError 重试
- **排重**: 已 grep 确认不在 F-001~089 / C-001~172 中；L559（押金回调单号）不同面
