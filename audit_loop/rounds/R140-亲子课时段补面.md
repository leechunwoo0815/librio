## [F-20260808-112] delete 软删时段无关联订单检查——已付费亲子课订单悬空（P3）

- **级别**: P3（低-中：业务保障缺失，付费订单悬空；触发依赖管理端删已预约时段）
- **位置**: backend/domain/parent_course_time/service.py:81-89（delete）
- **类别**: 删除无下游保护（模式⑤ 家族；F-096 delete_activity 同族——删除绕过关联保障）
- **事实**: delete 直接软删 slot（L84-85 `is_deleted = 1`）——**无 Order.parent_course_time_id 关联检查**；
  而 Order 有 FK 声明（order/models.py:86-88）——已付费家长订单关联该 slot
- **证据**:
  - service.py:81-89 无任何订单查询/存在性校验
  - order/models.py:86-88 `parent_course_time_id = Column(BigInteger, ForeignKey("parent_course_time.id"))`——
    订单明确关联时段
  - **R20 建议③ 未落地**：R20（L31）建议"软删 slot 前检查是否有关联订单（有则提示）"——**实现未采纳该建议**
  - **同类对照**：F-096（R110 activity delete 绕过 cancel——删除无退款/无通知）——同一"删除无下游保护"模式
- **触发**: 管理端删除已有家长付费订单关联的亲子课时段
- **影响**: ① 家长订单仍在但 slot 已软删 → 前端显示"时段不存在"或不可约；② 付费无退款无通知（家长钱已付
  课没了）；③ 管理端对账/排课混乱。低频（需删除已预约时段）+ 影响弱，P3
- **建议**: delete 前置检查 Order（parent_course_time_id == slot_id 且未取消），有关联则拒绝删除（提示先
  取消订单/退款）；或删除时通知关联家长 + 引导退款——与 F-096 修复同模式（删除必须闭环下游）
- **排重**: F-069（R20 时段校验）为 schema/service 校验面（创建侧），本条为删除侧——不同；grep 无
  "slot 删除/亲子课删除关联"历史；F-096（activity delete）为同族先例（不同实体）
