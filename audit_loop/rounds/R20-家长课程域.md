## [F-20260808-069] parent_course_time create/update 缺输入校验（end<start / 重叠时段 / 名额无下界） — P3

- **级别**: P3（观察项；管理端输入校验缺失，产品体验/数据质量，无资金/安全）
- **维度**: 4 API 契约（输入校验面）
- **文件**: `backend/domain/parent_course_time/service.py:52-79`（create/update）/ `backend/domain/parent_course_time/schemas.py:11-36`（Create/Update schema）
- **事实**:
  - `ParentCourseTimeCreate`（schemas.py:11-24）：course_date/start_time/end_time 均为 `str`（无格式/顺序校验），`max_participants: int = Field(default=10)`（**无 ge=1 下界**）
  - `ParentCourseTimeUpdate`（schemas.py:26-36）：同，字段可任意改
  - `service.create`（L52-67）直接建记录——**无"start_time < end_time"校验、无"同 venue 同日时间段重叠"校验**；`service.update`（L69-79）同
  - 可创建非法时段：end 早于 start（当天倒挂）、同场馆同日 9:00-10:00 与 9:30-10:30 重叠、max_participants=0 或负数
  - 用户端 `list_by_venue`（L26-38）直接展示 status==1 的全部时段——非法时段对用户可见
- **证据**: ① schemas.py 全（无 Field 约束）；② service.py create/update 无校验逻辑；③ 排重 grep：findings 无 parent_course_time 命中；R18 F-067（B3 名额竞态）为并发面，本项为输入校验面，互补
- **触发**: 运营在管理后台创建/编辑亲子课时段，输入错误时间（end<start、重叠）或 0 名额 → 用户端展示异常时段/可预约重叠时段
- **影响**: ① 用户端展示倒挂/重叠时段（产品体验差）；② 重叠时段可分别报名（B3 名额各自独立计数）——两名家长可约同一时间的不同 slot，教室/老师排期冲突；③ 名额 0/负数时 `paid_count >= max_participants`（R18 F-067 同校验）逻辑异常（0 名额永远满/负名额恒满）。无资金/安全。管理端低频 + 运营输入规范则不影响
- **建议**: ① schemas 加约束：`max_participants: int = Field(10, ge=1, le=100)`；② create/update service 校验 `start_time < end_time`（字符串 HH:MM 可比）+ 同 venue 同日时间重叠查询（`course_date==d AND start_time < new_end AND end_time > new_start`）；③ 可选：软删 slot 前检查是否有关联订单（有则提示）
- **排重**: 已 grep 确认不在 F-001~068 / C-001~112 中；R18 F-067（B3 名额并发竞态）不同面；C-070（R2 前端参数契约）不涉管理端 schema 约束
