## [F-20260808-071] create_question 未校验 correct_answer 合法性与 option 存在性——畸形题目致测验判分异常 — P3

- **级别**: P3（观察项；管理端输入校验缺失，数据质量 → 测验正确性；需运营创建畸形题才触发）
- **维度**: 4 API 契约（输入校验面）
- **文件**: `backend/domain/advancement/service.py:687-695`（create_question）/ `backend/domain/advancement/schemas.py:71-84`（CreateQuestionRequest）/ `:213-253`（submit_answers 判分）
- **事实**:
  - `CreateQuestionRequest.correct_answer: str = Field(..., min_length=1, max_length=1)`（schemas.py:80）——**只限 1 字符，不校验必须是 A/B/C/D**
  - option_c/option_d 为 `str | None`（schemas.py:78-79）——可空；**未校验"correct_answer 指向的 option 必须非空"**（如 correct_answer="C" 但 option_c=None 的题可创建）
  - `create_question`（service.py:687-695）`QuestionBank(**data.model_dump())` 直接入库——无 correct_answer 合法性校验、无 option 存在性校验、无 book_id 存在性校验
  - 判分逻辑（service.py:245）：`is_correct = question and question.correct_answer == selected`——correct_answer="X" 的题用户选 A-D 全判错；correct_answer="C" 但 option_c=None 时，用户选 C 判"正确"但前端无选项 C 可点（quiz 取题含 option_c=None，前端渲染缺失）
- **证据**: ① schemas.py:80 correct_answer 无 Literal["A","B","C","D"] 约束；② service.py:687-695 create 直接入库；③ service.py:245 判分逻辑对照；④ 排重 grep：findings 无"correct_answer 校验/畸形题"命中；F-026（搜索无 limit）不同面；F-057（取题泄漏答案）不同面
- **触发**: 运营在管理后台创建题目时 correct_answer 误填（如 "X"）或填 "C" 但未填 option_c → 题目入库 → 用户测验该题永远答错/前端无选项 C
- **影响**: 畸形题目导致测验判分异常（用户正确作答被误判 / 选项缺失无法作答）→ 影响测验通过率与晋级判定（F-057 已证测验影响晋级）；无资金/安全。管理端低频 + 运营输入规范则不影响
- **建议**: ① CreateQuestionRequest.correct_answer 改 `Literal["A","B","C","D"]`（Pydantic 枚举校验）；② create_question service 校验"correct_answer 指向的 option 非空"（A→option_a 必填，C→option_c 必填）；③ 校验 book_id 存在；④ 导入（bulk_import）同校验
- **排重**: 已 grep 确认不在 F-001~070 / C-001~115 中；F-026（搜索无 limit）与 F-057（取题泄漏）不同面
