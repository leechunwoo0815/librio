## [F-20260808-093] update_question 未校验 correct_answer 指向的 option 存在性（P3）

- **级别**: P3（低）
- **位置**: backend/domain/admin/services/book_service.py:252-267（update_question）；backend/domain/admin/admin_schemas.py:815-830（UpdateQuestionRequest）
- **类别**: 同类漏改第 3 点（模式① 家族；F-071 create → F-088 bulk → F-093 update）
- **事实**: update_question 直接 `setattr(q, field, value)` 落库（L262-264），**无"correct_answer 指向的 option 非空"校验**——correct_answer="C" 而 option_c 可传 None/空时畸形题目入库
- **证据**:
  - admin_schemas.py:826 correct_answer 有 `pattern="^[ABCD]$"`（格式已挡，优于 F-071 的 create 面）——但 L822-825 option_c/option_d 仍可 None，schema 不校验"A→option_a 必填"语义
  - book_service.py:262-264 无任何 option 存在性检查，直接 setattr
  - 对照：F-071（R23 create_question 未校验）+ F-088（R71 bulk_import_questions 未校验）——同缺口第三次出现，模式 1「同类漏改」防复发红线
- **触发**: 管理端编辑题目：correct_answer 改 "C" 但 option_c 留空/清空 → 落库
- **影响**: 畸形题目致测验判分异常（F-071 已证判分链 impact：正确作答被误判）→ 影响测验通过率与晋级判定；管理端低频 + 运营规范输入则弱
- **建议**: ① update_question 增加与 create 同款校验（correct_answer 指向 option 非空，若本请求修改了 correct_answer 或相关 option）；② 或 schema 加 model_validator 联动校验；③ 修复时按防复发红线 1：同时核 create（F-071）/bulk（F-088）/update（F-093）三入口
- **排重**: F-071（create）/F-088（bulk）已报不同入口；update 面首次。grep 确认无历史记录

## [F-20260808-094] list_bookcopies 硬编码 limit(500) 静默截断，无分页（P3）

- **级别**: P3（低）
- **位置**: backend/domain/admin/services/book_service.py:57-59；backend/domain/admin/routers/admin_books_router.py:171-177
- **类别**: 数据可见性缺口（管理端列表功能面）
- **事实**: list_bookcopies `query(BookCopy).filter(is_deleted==0).limit(500)` 硬编码上限，**无 page/page_size 参数**（router L171-177 无任何查询参数）→ 副本总数 >500 时第 501+ 副本静默截断，管理端不可见不可操作
- **证据**:
  - book_service.py:58 `.limit(500)` + router 无分页参数（对照 list_borrows R36 有 page/page_size 分页，venne list_venues R108 有 page/page_size）
  - BookCopy 为增长表：每本书多副本（batch_generate_copies 单次最多 100，可反复生成）→ 图书馆规模数百书 × 多副本极易破 500
- **触发**: 副本总数超 500 → 管理端副本列表只剩前 500
- **影响**: 第 501+ 副本无法从管理端查看借阅人/维修/报废/状态流转（set_copy_status 依赖 list 找到 copy_id）；F-086 已证 barcode 无唯一约束 → 用户借还扫描到的副本可能正是被截断不可见的副本，管理盲区
- **建议**: 加分页（page/page_size，与 list_venues/list_borrows 对齐）或至少游标；截断时返回 total/has_next 提示
- **排重**: F-026 是搜索无 limit（性能面），本条是列表有 limit 但截断不可见（功能面），不同；R36 C-129（borrow 管理端）有分页与本条无冲突

## [F-20260808-095] batch_generate_copies 并发调用生成重复条码（P3）

- **级别**: P3（低）
- **位置**: backend/domain/admin/services/book_service.py:269-310（batch_generate_copies）
- **类别**: 先查后改无锁（模式⑦ 家族，×8）+ barcode 无唯一约束（F-086）叠加
- **事实**: barcodes 生成规则确定（`{isbn}-{i+1:04d}`），existing_barcodes 预查重**非 with_for_update**（L280-285）→ 两管理员同时（或重试）对同一 isbn 同 count 调用：双方预查重都查不到 → 双写相同 barcode 副本；且 BookCopy.barcode 无唯一约束（F-086 已报，DB 不挡）
- **证据**:
  - book_service.py:279 barcode 确定性生成；L280-285 普通 query 预查（无 with_for_update）；L294-300 add+flush 后 existing_barcodes **未更新**（本批 barcodes 因 i 递增天然唯一，但跨请求无防护）
  - F-086：BookCopy.barcode 列无 unique → 重复条码可落库
  - router：batch_generate_copies 无任何并发控制
- **触发**: 双管理员同时"批量生成 100 本"同一 ISBN / 或前端重试双击
- **影响**: 相同 barcode 多副本并存 → 借还扫描 barcode 歧义（扫到哪本不确定）→ 借阅记录错绑；库存 total/available 被重复累加（L298-299）
- **建议**: ① barcode 加 unique=True（F-086 建议，DB 层兜底）；② 生成用唯一后缀（uuid 短码/token）替代纯递增；③ 或对 isbn 行 with_for_update 串行化（参照 R31 borrow 锁分层模式）
- **排重**: F-086 报的是"模型无唯一约束"（数据面），本条是"生成流程无锁可并发重复"（操作面），同一缺口两入口，独立报；F-066/075/076（先查后插）同家族但不同实体
