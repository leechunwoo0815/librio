## [F-20260808-099] migrate_account 后旧账号未禁用/未标记——旧微信仍可登录产生新数据（P3）

- **级别**: P3（低-中：数据分裂/管理混乱；触发依赖用户迁移后回旧微信操作）
- **位置**: backend/domain/admin/services/guardian_service.py:29-92（migrate_account）
- **类别**: 迁移收尾缺失（状态守卫/终态标记缺口）
- **事实**: migrate_account 迁走 Child/Order/RefundApplication/SystemMessage（L53-77）后，**旧账号 User 无任何处理**——status 仍 ACTIVE（user/models.py:30-36）、is_deleted 仍 0 → 旧 openid 仍可正常登录
- **证据**:
  - guardian_service.py:79-92 迁移完成仅 commit + 日志，无旧账号禁用/标记
  - user/models.py:30-36 status 默认 ACTIVE（1=启用 0=禁用），migrate 未触碰
  - User 表无"已迁移"标记字段（grep 确认无 migrate/disabled 字段）
  - **数据维度核查**：迁移后新数据仍挂旧账号——DepositRecord（child_id 维度，随孩子走 ✓ 不受影响）、BorrowRecord/ActivityEnrollment（child_id 维度 ✓）——但**新登录旧账号后可新建 Order/借阅/报名（user_id 挂旧账号）**，新账号不可见 → 数据分裂
- **触发**: 用户换微信完成迁移后，旧微信仍能登录（进入空壳账号），若在旧账号下继续操作 → 新数据挂旧账号
- **影响**: ① 新数据分裂（新账号看不到）；② 旧账号空壳长期存活，管理端账号列表混乱；③ F-083（consent 漏迁）叠加后旧账号残留合规记录无法追溯。低频 + 用户不会经常回旧微信，P3
- **建议**: ① migrate 完成将旧账号 status=0 禁用（或加"已迁移"标记字段）；② 旧账号禁用后旧 openid 登录提示"账号已迁移，请使用新账号"；③ 迁移收尾统一走终态（对照 F-077 账号接管修复时同链处理）
- **排重**: F-083（R52 consent 漏迁）是迁移**内容**面，本条是迁移**收尾/禁用**面，不同；grep 无"迁移后禁用/旧账号"历史
